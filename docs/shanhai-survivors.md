# 山海拾遗 —— 手机端弹幕天堂肉鸽 · 规格

## 一页速览（冷启动只读这里）

- **一句话**：手机横屏的弹幕天堂肉鸽，山海经题材，单手走位 + 自动开火，一局 8~12 分钟。
- **形态**：纯静态网页（HTML + Canvas 2D + 原生 JS，零依赖、**严格不联网**）→ 后期套壳成 Android 安装包。
- **内容**：6 神系（开局 3 + 试炼解锁 3）= 18 武器 + 24 被动 + 18 血统配方 + 6 角色；**第一版只做开局 3 系**（9 武器 + 12 被动 + 9 配方 + 3 角色）+ 1 个 Boss（相柳）+ 5 种敌人 + 1 张竞技场。
- **机制核心**：道具**只修改 24 条修饰器通道**（不描述组合），"意料之外的效果"由通道相乘自行涌现；另有 **5 个触发钩子**提供行为层的叠乘。
- **关键约束**：武器槽 4 + 被动槽 5（本规格原文写 3/4，**实现为 4/5，以 `shanhai-ultimate-rework.md` §9 为准**）；升级三选一、不可刷新；**无永久数值成长**，局外只有最高分 + 图鉴 + 试炼；Boss 通关制 + 通关后可选无尽。
- **美术**：程序生成占位图 + 资源清单回退（替换正式美术**不改游戏逻辑**）；中文字体用 **OFL-1.1 像素字体 + 子集化**；素材只用 CC0 / OGA-BY。
- **交付分期**：批 1 = 能连续通关与失败且三系各自可通关；批 2~4 = 三个解锁系各一个内容包；正式美术可随时替换。
- **本文件用法**：**先只读本节**；需要细节再按小节名局部读（`offset`/`limit`），不要全文通读。

## Problem Statement

我想做一个自己的小肉鸽，但在动手前就撞上了四堵墙：

1. **我想要的玩法在手游上很少见。** 我喜欢以撒那种"道具叠在一起产生无法预料效果"的惊喜，也喜欢吸血鬼幸存者"两种武器合成超武"的爽感。但手机上的同类游戏大多只有单一流派，一局下来构筑没什么变化，也缺少那种"我超，这俩居然能这么玩"的时刻。
2. **参考实现抄不了。** 我找了一圈开源同类项目，最常被推荐的那个（`bones-ai/c-blob-survival`）根本没写许可证，等于默认版权保留；有的写着 GPL，闭源上架直接违规；有的代码是 MIT 但素材是从 Asset Store 或别的游戏扒来的，不能随游戏分发。**我不知道哪些能看、哪些绝对不能碰。**
3. **个人做手游会被三件事劝退**：美术（我不会画画，也没装任何美术软件）、性能（几百个敌人加满屏弹幕，手机上跑不跑得起来）、合规（听说国内上架要版号、软著、防沉迷，个人根本办不下来）。
4. **手机上玩肉鸽的体验很差**：一局动辄半小时，通勤路上被打断就全没了；竖屏单手操作在弹幕游戏里根本躲不开。

我不需要别人替我写完这个游戏，我需要一份**把上述四堵墙都拆掉或绕开的、能直接开工的详细要求**。

## Solution

我拿到一份规格，它把"一个手机上的山海经肉鸽"拆成了可以照着做的样子：

- **玩法**：横屏、单手走位、自动开火、一局 8~12 分钟；开局三个神系（山经 / 海经 / 大荒经），通过"试炼"解锁另外三个（天问 / 灵山 / 昆仑）；每局能带 3 把武器 + 4 件被动，池子里有 18 把武器、24 件被动，**每一件都只做"修改参数通道"这一件事**，所以它们叠在一起会自己长出意料之外的效果；另有 18 条**明牌融合配方**（本系武器满级 + 本系某件被动 → 超武），给"我这局在攒什么"这件事一个明确目标。
- **中断友好**：一局的状态可以序列化，退出后回来能接着打。
- **美术不劝退**：先由程序生成"占位图形"（每个系一套主色、每类弹道一个几何形状、每件道具一个符号），**正式美术到位后只需要往资源清单里填文件，不改一行游戏逻辑**；正式素材优先使用 CC0（免署名、可商用、零法律灰区）。
- **性能有底**：固定步长、对象池、空间哈希，规格里给出同屏实体与弹幕的硬上限与兜底开关。
- **合规有路**：严格不联网 → 走 TapTap「正式上线 试玩版」+ TapPlay 沙箱，**不需要版号、软著、ICP 备案**，防沉迷由 TapPlay 豁免；规格里同时列出隐私政策页、关于/许可页、老 WebView 降级提示这三件"缺了就上不了架"的必做项。
- **可抄与禁抄清单明确**：哪些开源项目的架构思路可以照抄、哪些代码绝对不能碰、哪些素材许可证有雷，全部写明。

## User Stories

1. As a **第一次玩的玩家**, I want 打开就进游戏、不注册不登录, so that 我在通勤路上能立刻开始玩。
2. As a **第一次玩的玩家**, I want 30 秒的"空窗期"只有零星弱敌, so that 我能在死之前先弄明白怎么走位。
3. As a **第一次玩的玩家**, I want 攻击全自动、我只需要移动, so that 我一根拇指就能玩。
4. As a **第一次玩的玩家**, I want 清楚的横向屏幕布局（左下摇杆、右下按钮、上方血条与计时）, so that 我不会因为找不到按钮而死。
5. As a **玩家**, I want 每次升级从 3 张卡片里选 1 张, so that 我做的是有代价的取舍而不是收菜。
6. As a **玩家**, I want 卡片上标明它属于哪个神系, so that 我能有意识地朝某个方向搭建。
7. As a **玩家**, I want 武器槽只有 3 个、被动槽只有 4 个, so that 我每一局都必须放弃大部分内容。
8. As a **玩家**, I want 每一件道具只做"改一个参数通道"这一件事, so that 两件道具叠在一起时能自己长出我没预料到的效果。
9. As a **玩家**, I want 触发类效果（命中时 / 击杀时 / 受伤时 / 每 N 秒 / 波次开始时）能与参数通道交叉, so that 我能搭出"击杀爆炸 + 命中分裂"这种连锁反应。
10. As a **玩家**, I want 每把武器满级后与指定被动合成"超武", so that 我这一局有一个明确的、值得规划的目标。
11. As a **玩家**, I want 融合配方是明牌的（我可以提前知道要凑什么）, so that 我的攒牌有方向感而不是纯碰运气。
12. As a **玩家**, I want 一局 8~12 分钟, so that 我能在一次通勤里打完一整局。
13. As a **玩家**, I want 第 10 分钟出现最终 Boss 相柳, so that "我赢了"这件事有一个可见的终点。
14. As a **玩家**, I want 难度按每 2 分钟一档阶梯式跃升, so that 我能感觉到"刚才怎么突然变难了"，而不是被温水煮青蛙。
15. As a **玩家**, I want 第 5 分钟开始出现远程敌人, so that 我必须学会绕而不是一直站在原地转圈。
16. As a **玩家**, I want Boss 战之前有清场预警和音乐切换, so that 我知道"要来了"。
17. As a **玩家**, I want 打死 Boss 就是通关结算, so that 失败时的挫败感变成"我差一点就赢了"。
18. As a **玩家**, I want 通关后可以选择继续打无尽模式, so that 我玩得好的那局能继续刷下去。
19. As a **玩家**, I want 无尽模式每 2 分钟加一档难度, so that 它不会变成无限挂机。

## Implementation Decisions

### 0. 产品形态与技术栈

- **形态**：单页网页游戏（HTML + Canvas 2D + 原生 JavaScript），纯静态、零依赖、零构建期框架。
- **分发链**：网页版（PWA，可"添加到主屏幕"）→ 后期用 WebView 容器方案套壳成 Android 安装包。**第一版不做套壳。**
- **平台**：Android 优先；iOS 不构建、不签名（需要 Mac），只保证网页版在移动浏览器里可玩。
- **横屏**：固定逻辑分辨率 + 等比缩放留黑边（letterbox），**不做自适应拉伸**。
- **不引入游戏引擎**。理由见 Further Notes「关键取舍」。
- **逻辑与渲染分层**：模拟层不得引用任何渲染 API；渲染层只读模拟状态。这条是"以后换 WebGL 渲染器不用改逻辑"的前提。

### 1. 术语（本文档内定义，后续不再解释）

| 术语 | 含义 |
|---|---|
| **神系（系）** | 内容分组单位，6 个：山经 / 海经 / 大荒经 / 天问 / 灵山 / 昆仑。每个系拥有 1 个角色、3 把武器、4 件被动、3 条配方 |
| **修饰器通道** | 道具唯一能修改的参数，共 24 条。道具**不描述组合**，只改通道 |
| **触发钩子** | 5 个事件点：命中时 / 击杀时 / 受伤时 / 每 N 秒 / 波次开始时 |
| **血统配方** | 明牌的融合规则：某把武器满级 + 某件指定被动 → 该武器的超武形态 |
| **超武** | 配方触发后武器的强化形态，一局内永久 |
| **试炼** | 一次性解锁任务，唯一的局外进度载体 |
| **素体** | 玩家角色的形态概念：一个无定形幼体，每拿一件道具就长出一个器官/特征 |
| **资源清单** | 槽位 id → 资源文件的登记表；缺文件时回退为程序生成的占位图 |
| **占位图** | 程序生成的简单几何/符号图形，用于在正式美术到位前让游戏可玩、可测 |
| **一局（run）** | 从开局到死亡或通关的一次完整游玩，时长 8~12 分钟 |
| **断点续局** | 一局中途退出后，下次进入可恢复该局 |

### 2. 修饰器通道（24 条）—— 本作的核心契约

道具只修改这些通道。**通道之外的任何行为都必须由钩子表达。**

| # | 通道 | 所属系 | 叠加规则 | 说明 |
|---|---|---|---|---|
| 1 | 最大生命 | 山经 | 加法 | 提升生命上限，按差值同步补血 |
| 2 | 减伤 | 山经 | 加法（有硬上限） | 百分比减伤，**上限必须 < 80%** |
| 3 | 移速 | 山经 | 加法（乘基础值） | 影响走位与躲弹 |
| 4 | 击退 | 山经 | 加法 | 命中时的推力 |
| 5 | 弹道数 | 海经 | 加法 | 每次开火的投射物个数 |
| 6 | 弹速 | 海经 | 乘法 | 投射物飞行速度 |
| 7 | 穿透 | 海经 | 加法 | 投射物可穿过的额外敌人数 |
| 8 | 拾取半径 | 海经 | 加法 | 经验与掉落物的自动吸附半径 |
| 9 | 范围 | 大荒经 | 乘法 | 作用半径与判定尺寸 |
| 10 | 持续伤害 | 大荒经 | 加法 | 附着在敌人身上的每秒伤害 |
| 11 | 追踪强度 | 大荒经 | 加法 | 投射物的转向能力 |
| 12 | 伤害 | 大荒经 | 加法 | 全局伤害加成 |
| 13 | 暴击率 | 天问 | 加法（上限 < 100%） | 触发暴击的概率 |
| 14 | 暴击倍率 | 天问 | 乘法 | 暴击时的伤害倍数 |
| 15 | 射速 | 天问 | 乘法 | 开火频率 |
| 16 | 命中分裂 | 天问 | 加法（计数） | 命中后额外生成的子弹数 |
| 17 | 吸血 | 灵山 | 加法 | 造成伤害时的回血比例 |
| 18 | 诅咒 | 灵山 | 加法 | 使敌人受到的伤害提高（敌方易伤） |
| 19 | 闪避冷却 | 灵山 | 加法（秒，有下限） | 闪避技能的冷却缩减 |
| 20 | 召唤强度 | 灵山 | 乘法 | 召唤物的伤害与生命 |
| 21 | 回血 | 昆仑 | 加法 | 每秒自动回复 |
| 22 | 护盾 | 昆仑 | 加法 | 可再生的额外血量层 |
| 23 | 复活 | 昆仑 | 计数（默认 0） | 致死时消耗一层，原地复活并短暂无敌 |
| 24 | 击杀回血 | 昆仑 | 加法 | 每次击杀回复固定生命 |

**硬规则**：新增通道必须有"某件已确认的道具需要它"作为理由；禁止为了未来可能性预留通道。

### 3. 触发钩子（5 个）

`命中时` / `击杀时` / `受伤时` / `每 N 秒` / `波次开始时`。

- 钩子上只挂**已存在的通道效果**或**已有武器的一次开火**，不引入新通道。
- **通道相乘 = 数值上的意外，钩子相乘 = 行为上的意外**。两者交叉是"无法预料的效果"的两个来源。
- 钩子效果需要防止无限递归：由钩子触发的伤害**不再触发同类钩子**（同一帧内同一钩子最多触发一次）。

### 6. 局内流程（升级 / 槽位）

- **槽位：武器 3 + 被动 4。** 这个数字是"取舍是否成立"的核心参数，不得上调。
- 升级时**发 3 张卡，不可刷新、不可跳过**（跳过一次等于免费观望，会破坏取舍）。
- 卡片来源优先级：未满级武器升级卡 / 未持有被动 / 未持有武器；槽位满后**只发"升级已有武器"的卡**。
- 卡片必须显示**所属神系标签**。
- **初始武器由角色决定**（每系武器 ①），不是玩家自选。
- 复活类效果（陆吾守）在一局内可累积多层，触发时清空该层。

### 7. 一局节奏（时间驱动）

| 时间 | 事件 |
|---|---|
| 0:00–0:30 | 空窗期：少量最弱敌人 |
| 0:30–2:00 | 密度爬升，开始掉落升级 |
| 2:00 / 4:00 / 6:00 / 8:00 | 4 次精英（换色放大 + 词缀） |
| 2:00 起 | 每 2 分钟一档**阶梯式**提升敌人生命/速度/数量（不是连续爬坡） |
| 5:00 起 | 开始出现远程敌人 |
| 9:30 | 清场预警 + BGM 切换 |
| 10:00 | Boss 相柳登场 |
| 10:00–12:00 | Boss 战；击杀 = 通关结算 |
| 通关后可选 | 无尽模式，每 2 分钟 +1 难度档 |

- **敌人速度上限必须低于玩家移速**（让兽潮被拖成一条尾巴，玩家永远跑得掉）——这是手感层的硬性设计决策。
- 刷怪位置：环形生成，且**大部分刷新在玩家移动方向的前方**。

### 9. 角色与素体

- 每个系 1 个角色（山魄 / 海魄 / 荒魄 / 天魄 / 巫魄 / 不死魄），随系解锁。
- **角色差异只有三项**：① 初始武器（该系武器 ①）；② 开局自带 1 件该系被动（该被动同时仍在池中）；③ **双向微调**——本系一条通道 +8%、另一条通道 −5%。
- **禁止"纯增益"角色**（会出现最优解）；**禁止幅度超过 10%**。
- **素体机制全角色通用**：每持有一件道具，角色外观上多一个挂件/器官（复用道具图标的小尺寸版本），槽位上限 7 也就是最多长出 7 个特征。

### 10. 状态与存档（内联字段契约）

`RunState`（可完整序列化，用于断点续局）：

| 字段 | 说明 |
|---|---|
| `seed` | 本局随机种子（用于可复现与调试） |
| `characterId` | 角色 |
| `elapsedMs` / `waveIndex` | 时间与波次进度 |
| `player` | 生命、护盾、等级、经验、复活层数 |

**不进存档**：敌人、子弹、掉落物、伤害数字——续局时按波次冷启动恢复。
**全局存档**：最高分 / 图鉴 / 试炼进度 / 解锁 / 设置 / `RunState`，并带版本号与迁就逻辑（版本不匹配时丢弃未完成的一局而保留解锁进度）。

### 11. 性能与渲染

- 固定步长模拟（60 Hz），渲染与模拟解耦。
- **对象池覆盖**：敌人、玩家子弹、敌方子弹、掉落物、伤害数字、粒子。
- **空间哈希 broad-phase**：敌人与投射物的邻近查询不得使用全表线性扫描。
- **硬上限（超限时不再生成而不是掉帧）**：同屏敌人 300、同屏弹幕 800、同时伤害数字 40。
- **兜底开关**：画质档（特效开 / 关）、屏震、伤害数字；低端机自动降档。
- 像素图缩放使用整数倍；避免滤镜与实时旋转，除非实测无影响。
- 首帧必须早于 2 秒出现（黑屏超过 2 秒是差评来源）。

### 12. 美术：占位生成 + 资源清单（可替换性的关键）

- **画风 = 像素风，以 16×16 网格为基准单位**（道具图标显示尺寸约 24×24）。理由：中文字体已定为像素字体（第 13 节）；程序生成 16×16 像素图形是确定性的、可参数化的；且免费 CC0 素材的存量压倒性集中在像素风。像素图缩放**只用整数倍**。
- **资源清单字段**：`槽位 id / 类别 / 文件 / 宽高 / 锚点 / 帧数 / 许可 / 来源 URL / 下载日期 / 占位生成器 id`。
- 游戏逻辑**只引用槽位 id**，永远不引用文件名。
- 清单中缺失文件的槽位 → 自动调用该槽位的**占位生成器**产出图形：每系一套主色、每类弹道一个几何形状、每件道具一个符号；**开发模式下在图上叠加槽位标签**。
- **替换正式美术 = 往清单填文件 + 登记尺寸与锚点，不改游戏逻辑。**
- 槽位清单（批 1）：玩家角色 ×3、普通敌人 ×5、Boss ×1、竞技场地面与障碍 ×1 套、武器投射物 ×9、道具图标 ×12、UI（主菜单 / 局内 HUD / 三选一弹窗 / 结算 / 图鉴 / 试炼 / 关于）、特效（命中 / 爆炸 / 升级 / 拾取）。
- **素材现实的硬事实（已查证，像素级）**：严格中国题材的**顶视角**素材在 OpenGameArt 上**为零**——`chinese` / `oriental` / `asian` / `temple` 与 `Top Down` 标签的交集**全部为 0**，而单独 `Top Down` 有 181 条（过滤器有效，证明这些 0 是真 0）；全站 181 条顶视 2D 素材逐页看过后，东亚题材只剩 1 条，且只是 3 张低清 JPG。`shanhaijing` / `xingtian` / `nine tailed fox` 检索均为 0 条。因此**玩家角色、普通敌人、Boss、投射物、道具图标这五类槽位没有现成素材可用**——程序生成不是权宜之计，而是**唯一可行路径**；这正是本规格把"占位美术 + 资源清单"做成正式机制、而不是临时手段的原因。
- **素材底座（风格自洽，全部 CC0 或免署名）**：① **中立地形的顶视角 CC0 瓦片**——OpenGameArt 上带 `Top Down` 标签的 CC0 2D 素材共 **100 件**，可直接支撑竞技场地面与障碍；② Kenney 的**像素** 16×16 包（`roguelike-caves-dungeons` 为一张 492×305 图集、含 522 个 16×16 瓦片；`roguelike-rpg-pack` 1700 文件）；③ Kenney 的 UI 与音频包（与画风无关）。⚠️ **必须避开的坑**：Kenney 带 `top-down` 标签的两个包（`top-down-shooter`、`tower-defense-top-down`）是**扁平矢量风**（包内含 SVG），**与像素风不兼容，不能当作像素风的素材底座**。
- **素材来源优先级**：CC0 > OGA-BY > CC-BY。**任何 CC-BY-SA / GPL 素材一律禁用**（ShareAlike 与 copyleft 会传染闭源分发）。
- **每份第三方素材必须登记 URL + 下载日期 + 许可原文或截图**（平台要求"素材若为原创须提交真实有效的证明"，且社区已有 CC0 素材被伪造版权主张导致下架的真实前例）。
- 若使用 AI 辅助生成素材，**必须保留生成记录与人工修改的过程文件**，并建立"人类创作"证据链。
- **不做四向行走动画**：顶视角单位只做静态 + 朝向/浮动 + 受击帧。**这一条直接决定美术量能否减半。**

### 13. 中文字体

- 选型：**OFL-1.1 的像素中文字体**（方舟像素字体 / Fusion Pixel Font / 俐方體11號 / 美績点陣體任一）。**不得使用 Zpix**（商业授权单产品 USD $1000，且明文禁止修改/转换/拆分，连子集化都不允许）。
- **必须做子集化**：从游戏全部文案提取唯一字符集，裁到实际用字（预期 500~1500 字 → 像素字体约 50~150 KB）。
- 子集化必须遵守三条：① 保留许可元数据（`--name-IDs` 需全保留，或随包附完整 `OFL.txt`）；② **子集化属于 OFL 定义的 Modified Version，必须修改字体内部名**；③ 随包附「版权声明 + 许可声明 + 许可全文」。
- WebView 场景可用 woff2（体积小 5~7 倍）；**若日后改为原生打包，Android 只认 ttf/otf**。

### 14. 音频

- 音效与 BGM 使用 **CC0 来源**（Kenney 的 Interface / RPG / Digital / Impact / Music Jingles 系列；OpenGameArt 的 SubspaceAudio 音效集与 Chiptune 循环）。**不用需要注册或混有 NC 许可的音效库。**
- 素材包打底 + **WebAudio 合成做动态变调**（连击越高音调越亮、暴击叠加音）。
- **移动端硬约束**：① 音频上下文的恢复必须发生在**用户手势直接触发**的处理函数里（放进定时器无效）；② iOS 切后台后音频上下文会进入中断态，**每次回到前台都要重新恢复**，不能"解锁一次了事"；③ Android WebView 默认比 Chrome 更严格地要求用户手势；④ 移动端音频缓冲约 43~46 ms，**连发音效必须预渲染或限流**，否则会糊；⑤ 不要硬编码采样率，读取设备实际采样率后离线预渲染。
- **必须有静音开关**，且设置需要持久化。

## Testing Decisions

**原则：只测外部行为，不测实现细节。** 不断言内部函数怎么组织、不断言某个私有方法被调用；只断言"给定输入，游戏状态与可见结果如何"。

**必须测的模块与行为**：

1. **单局可通关性（无头模拟）**：固定种子、无渲染、快进跑完一局。断言：能打到 Boss、能在合理构筑下击杀 Boss、能在不做任何选择时死亡。**三系各自的初始武器都要能单独通关一次**（这是"每系可用"的最小定义）。
2. **通道求值**：对任意两件道具组合（24×24 全枚举，含与钩子叠加）计算结果表。断言：无 NaN、无负数、无溢出；**减伤与暴击率不超过各自硬上限**；不存在"必杀一切"的单一组合（存在则视为平衡缺陷）。
3. **钩子递归防护**：构造"击杀时爆炸 + 命中时分裂"的组合，断言同一帧内不产生无限递归，且帧时间不爆炸。
4. **配方触发**：武器满级 + 对应被动 → 必定触发且只触发一次；条件不满足时不触发。
5. **升级流程**：槽位满时只出升级卡；卡片不出现已满级武器；一局内不出现超过 3 武器 / 4 被动。
6. **试炼与解锁**：六条试炼的条件判定（含"只用某系武器"的全程持有判定、跨局累计击杀）；达成后持久化；未达成不解锁。
7. **存档往返**：`RunState` 序列化 → 反序列化 → 继续，状态一致；版本不匹配时丢弃未完成的一局但保留解锁进度。
8. **断点续局**：模拟"中途退出 → 重开"，断言从对应波次继续且不重复结算奖励。
9. **性能预算**：在 300 敌人 + 800 弹幕的压测场景下断言帧率下限与内存稳定；**对象池计数在长期运行后不得增长**（池泄漏是最典型的失败）。
10. **触控与安全区**：横屏下摇杆与按钮不重叠、不被刘海/圆角遮挡；不同长宽比下画面比例正确、无拉伸。
11. **老内核降级**：模拟低版本 WebView，断言出现**提示页**而不是白屏或卡死（这是唯一会让玩家直接给差评的失败形态）。
12. **音频初始化**：在无用户手势时不得报错；手势后音频可用；切后台再回前台后音频仍可用。

**代码库先例（可参考其测试思路，不要抄代码）**：
- `Mocas-12/no-survivor-game`（MIT）在工程内自带 **headless 冒烟测试与平衡性测试**，是本项目"无头跑一局 + 平衡回归"的直接参考。
- `igogot/survivor-game`（**无许可证，只能读不能抄**）演示了**确定性固定步长 + 种子化**对可测性的价值：模拟中不出现时间/随机数直读，整局可用种子复现。
- `matthiasbroske/VampireSurvivorsClone`（MIT）的**对象池与空间哈希**是性能测试的对照物。

## Further Notes

### 关键取舍与理由（后人最容易问"当初为什么这么做"的三条）

1. **为什么不用游戏引擎？** 需要的三个核心模式（对象池、空间哈希、固定步长）在任何方案里都要手写；原生 Canvas 的产物是纯文本，**另一个 AI 实现者能完整地读、改、测**，而引擎的核心资产（场景文件）手写极易出错；零依赖还意味着体积小、无许可风险、无版本升级破坏。兜底方案是"逻辑层不动、把渲染层换成 WebGL"，所以规格强制要求逻辑与渲染分层。
2. **为什么严格不联网？** 这是"免费 + 无内购 + 不联网 → 只需防沉迷与隐私合规、走试玩版、豁免版号/软著/ICP 备案"这条通路的**前提**。代价是永久放弃排行榜与云存档，属**难逆转**的取舍，因此写在架构约束而非建议里。
3. **为什么同时要"修饰器管线"和"明牌配方"？** 两者解决的是不同需求：管线提供**意外**（通道相乘自然涌现），配方提供**目标感**（我可以提前规划）。少了前者，游戏失去肉鸽的核心惊喜；少了后者，玩家在一局内没有任何可规划的东西，构筑的选择乐趣会塌掉。

### 明确禁止使用的资源（禁令清单）

- **代码**：任何 `license: null` 的仓库（默认版权保留，如 `bones-ai/c-blob-survival`、`igogot/survivor-game`）；任何 GPL/AGPL 项目；含商业许可依赖的项目（如带 DOTween 的 Unity 模板）。
- **素材**：任何 **CC-BY-SA / GPL** 素材（ShareAlike 与 copyleft 传染）；任何游戏 IP 素材（宝可梦、Berserk 等）；OpenGameArt 的预览图（可能"All rights reserved"）；来源不可追溯的"素材汇总仓库"。
- **字体**：Zpix（商业授权 + 禁止子集化）；任何"免费商用但未授权修改"的自定义许可字体（子集化属修改）。
- **音效**：需要注册才能下载且有 NC 条款的来源；无法核实许可的站点。

**三条"看起来能用、其实不能用"（避免重复踩坑）**：

1. **`Ancient Chinese Character Pack 1`（CC0）不是精灵包** —— 8 个造型实际是 **420×713 ～ 1172×880 的大幅插画**，无动画、无方向，**不能当角色精灵使用**。
2. **`Chinese Icons`（CC0）只有 9 个图标**（实测 `48×48 = 3×3 × 16×16`），**填不满 12 个道具图标槽位**。
3. **Kenney 没有任何可当 Boss 的大尺寸单位**，且其 `top-down` 系列是**扁平矢量风**（详见第 12 节）。

**禁用清单（纯 copyleft，换许可也躲不掉）**：`Chinese dragon` = GPL 2.0-only；`Redlong` = GPL 3.0-only（尺寸最大、动作最全的中国龙，**只能看不能进包**）；`Carlo` = GPL 2.0-only；`Statues & Fountains Collection` = CC-BY-SA 3.0-only；`Whispers of Avalon: Dragon NPC` = CC-BY 3.0 **+ GPL 3.0**（含 GPL 即为雷）。

**送审前必须处理的三处许可自相矛盾（已查证）**：

1. **`Pixel Weapons` 挂着 CC0 徽章，但 Notice 逐字要求"商业使用须署名 Gabe Hess 并附 itch 链接"** → **不可凭 CC0 自证**，要么按署名处理，要么直接不用。
2. `Statues & Fountains Collection` 的许可字段、作者评论、描述**三层互相不一致** → 不用。
3. `Minimalist Chinese Temple` 的署名对象是**平台**而非作者（原文要求链接 opengameart.org）→ 若使用须按其原文处理。

**Provenance 记账的两条硬要求**：`/content/buddha-statues-32x32` 与 `/content/meditator-statues-32x32` 指向**同一个 node**，provenance 只能记一次；所有 URL 必须抄写正确（`fujin-statue-1` 这种后缀错误会让材料在送审时失效）。
